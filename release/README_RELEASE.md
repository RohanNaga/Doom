# Release runbook: publishing the DoomDiT benchmark and weights to Hugging Face

What Rohan runs, in order, once a Hugging Face account exists and the final checkpoints are on Spiderman. Everything runs on Spiderman (`rnagabhi@128.2.204.110`, CMU VPN, `/run-server` skill) under tmux with `TMPDIR` and `HF_HOME` on the data drive, because `/home` had 26 GB free and `/` 1 GB on 2026-09-16 and neither is ours. Nothing here touches Superman.

Files involved (all under `release/` unless stated):

| File | Role |
|---|---|
| `manifest.json` | every artifact to publish: source path on Spiderman (or `repo:` path in the checkout), published path, required or optional, notes |
| `upload.py` | `stage`, `checksum`, `upload`, `verify`, `weights-md`; all take `--dry-run`; stage, checksum and upload resume |
| `hf_upload.py` | step 1 only: converts `raw_arnold/ep_*.parquet` into the Hub shards (already done once; restartable) |
| `DATASET_CARD.md`, `MODEL_CARD.md` | become `README.md` of the dataset and model repos; `<hf-user>` is filled by `stage --user` |
| `checksums.json` | written by `checksum`: size, md5, sha256, git blob sha1 per staged file; committed after the run |
| `../WEIGHTS.md` | regenerated by `weights-md` from the manifest and checksums |

## 0. Before starting (decisions and prerequisites)

1. Hugging Face account and a **write** token (`https://huggingface.co/settings/tokens`). Export it as `HF_TOKEN` in the tmux session only; never write it into a file in the repo.
2. Pick the namespace (`--user`, e.g. the account name) and check the two repo ids in `manifest.json` (`{user}/doom-freedoom-arnold-320x240-lossless`, `{user}/doomdit-warm-starts`). Edit the manifest if you want other names; the cards reference them through `<hf-user>` only.
3. Visibility: the dataset is about 245 GB. Hugging Face's free private-storage allowance is smaller than that (100 GB per account at last check <!-- VERIFY current limits at https://huggingface.co/docs/hub/storage-limits -->), so either upload the dataset repo public from the start or confirm the account's quota. Public research datasets have been accepted at this size; if the upload is refused for quota, open a request with the Hub before retrying.
4. Resolve the items marked `<!-- VERIFY -->` in the two cards. The ones that need a decision rather than a lookup:
   - whether `full_deathmatch_unseen2.wad` ships (it embeds Arnold's WAD lumps; the Arnold repo has no licence file) or only `curation_manifest.json` plus the build script; move the WAD out of `tmp/unseen2/` either way, since the manifest points at `tmp/unseen2/full_deathmatch_unseen2.wad`;
   - the paper title in both citation stubs;
   - whether the legacy April checkpoint is included (`legacy_april_dit_xl2/`, optional; fetch it with `download_weights.sh` if no copy is on Spiderman).
5. Final numbers: run `paper/make_tables.py` after `paper/sync_results.sh` and paste the regenerated tables into `MODEL_CARD.md` (cells marked VERIFY), or leave the Sep 16 values and say so.
6. Confirm the checkpoints named in the manifest exist: `results_spiderman/{030,031,032,033}-*/best.pt`, `snap_0090000.pt`, `040-unidiffuser-l32-aligned` (after Sep 19), `050-skyreels-l8-flow`, `idm_aligned{,_k2}/idm.pt`, `vae_decoder_arnold_lpips/vae`. `stage --dry-run` lists what is missing.

## 1. Session setup on Spiderman

```bash
ssh rnagabhi@128.2.204.110
tmux new -s hf-release
export D=/sata2/data/rnagabhi/doom
export TMPDIR=$D/tmp/tmpdir HF_HOME=$D/hf HF_HUB_ENABLE_HF_TRANSFER=0
mkdir -p $TMPDIR $D/hf_staging
export HF_TOKEN=hf_...            # paste; do not put it in a file
cd $D/repo && git pull
PY=~/miniconda3/envs/doom/bin/python
$PY -c "import huggingface_hub as h; print(h.__version__)"   # need >= 0.25 for upload_large_folder; else: $PY -m pip install -U huggingface_hub
df -h /sata2/data                                            # staging by hardlink costs no space; a copy would need 265 GB
```

The tmux server does not inherit a later `export`, so put `TMPDIR=... HF_HOME=...` in front of any command you start in a *new* tmux window (the Sep 16 lesson in `RESEARCH_CONTEXT.md`).

## 2. Shards (skip if `hf_release_arnold/data/train-*.parquet` is complete)

```bash
ls $D/hf_release_arnold/data | wc -l          # expect 227 <!-- VERIFY -->
# only if incomplete: restartable, keeps existing shards, about 1 to 2 h for 202 GB
$PY release/hf_upload.py --in-dir $D/raw_arnold --work-dir $D/hf_release_arnold
```

## 3. Stage

```bash
$PY release/upload.py stage --staging $D/hf_staging --user <hf-user> --dry-run    # lists MISSING REQUIRED and absent optional entries
$PY release/upload.py stage --staging $D/hf_staging --user <hf-user>              # hardlinks (same filesystem, no extra disk), seconds
```

Fix every `MISSING REQUIRED` line before continuing (wrong path in the manifest, or the artifact is not there yet). Rerunning `stage` is idempotent; the cards and the manifest copy are refreshed every time, so after editing a card just run `stage` again.

Disk: `du -sh $D/hf_staging` reports the full size (about 265 GB) even though hardlinks share the blocks; `df` is what tells you nothing was consumed.

## 4. Checksums

```bash
$PY release/upload.py checksum --staging $D/hf_staging --out release/checksums.json
```

Reads every staged byte once (md5, sha256 and git sha1 in one pass): about 265 GB at the drive's sequential rate, 30 to 60 minutes. Resumable: files whose size and mtime are unchanged are not re-read. Commit `release/checksums.json` afterwards.

## 5. Upload

```bash
$PY release/upload.py upload --staging $D/hf_staging --user <hf-user> --dry-run
$PY release/upload.py upload --staging $D/hf_staging --user <hf-user> [--private] --workers 4
```

`upload_large_folder` splits the work into many commits, keeps its state in `$D/hf_staging/<repo>/.cache/.huggingface/`, and resumes if the session dies: rerun the identical command. Time is bandwidth-bound: 245 GB dataset plus about 20 GB of weights is 1.5 h at 50 MB/s and 7 h at 10 MB/s <!-- VERIFY Spiderman's uplink with a first shard -->. Run it detached in its tmux window and check `tmux attach -t hf-release` later. Do not edit files under the staging tree while it runs.

## 6. Verify

```bash
$PY release/upload.py verify --user <hf-user> --checksums release/checksums.json
```

Lists both repos and compares every file's size and hash (LFS sha256 for parquet, `.pt`, `.safetensors`, `.wad`; git blob sha1 for small text files) against `checksums.json`; exits 1 with the missing or mismatched paths. The Hub never exposes an md5, so the md5 column in `WEIGHTS.md` is for people who download; `verify` checks what the Hub can confirm.

## 7. WEIGHTS.md and the repo

```bash
$PY release/upload.py weights-md --checksums release/checksums.json --user <hf-user> --out WEIGHTS.md
git add WEIGHTS.md release/checksums.json release/manifest.json release/DATASET_CARD.md release/MODEL_CARD.md
git commit -m "publish benchmark and weights to hugging face"
```

Then, on the Hub: make the repos public if they were private, check that the dataset viewer renders `data/` (the `configs` block in the dataset card points it at `data/train-*.parquet`), and put the two URLs into the paper's data-availability sentence and `RESEARCH_CONTEXT.md` section 0.

## 8. Adding artifacts later (PixArt evaluation, UniDiffuser, unseen2, final tables)

Rerun steps 3 to 7. `stage` links only the new files, `checksum` hashes only them, `upload` pushes only what changed, `verify` re-checks everything, `weights-md` replaces the placeholder rows. Card edits alone: `stage` then `upload` (a README-only commit).
