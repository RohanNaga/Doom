## Verdict

**Training: conditional GO.** No indexing, objective or conditioning defect was found in the reviewed code paths or in the sampled raw data. The causal contract (frame at row i, control leaving row i, target `latents[r]`, controls `buttons[r-32:r]`) holds in the released recordings and in every code path that builds a training window, a rollout step or a horizon step. No recipe choice would waste the runs. GO is conditional on the five pre-launch checks in section 7.1: the gates as written do not audit the training corpus's sidecars against the raw recordings, never check that stored latents belong to the rows their sidecars describe, and allow the code to change after the gates pass.

**Evaluation pipeline: NO-GO as the source of paper numbers.** `scripts/spiderman/after_nexttic.sh` scores validation, test and unseen in one unattended pass, rolls out on test independently of the requested corpora, and caches by file existence. The frozen unseen subset is dominated by a control regime the model barely trains on (finding H1). None of this blocks training. All of it must be fixed before comparative scoring starts.

## 1. Ranked findings

Severity: **H** high (changes what a claim can say, or can silently corrupt a result or the launch), **M** medium (weakens a claim or the protocol), **L** low (documentation or robustness).

### H1. The frozen unseen subset is 85% worker-first episodes, a control regime that is 1.6% of training and absent from val and test

- **Evidence (measured).** Arnold's weapon-select requests (executed bits 9 to 18) can execute only in a recorder process's first episode, k = 0 (mechanism in `release/DATASET_CARD.md:98-108`). I measured k from the raw `buttons` column of each episode with `transitions.button_width_report`:

  | Set | Episodes | k = 0 (weapon-select requests can execute) | Episodes with executed switches |
  |---|---:|---:|---:|
  | train 0:2000 | 2,000 | 32 (1.6%), ids 0 to 31 (sample of 96: ids 1 and 22) | 32 at most; the corpus report counts 3,286 executed switch rows in total (`RESEARCH_CONTEXT.md` 2026-09-22 13:00) |
  | val 6000:6100 | 100 | 0 (k = 187 to 190) | 0 |
  | test 7000:7100 | 100 | 0 (k = 218 to 221) | 0 |
  | **unseen 0:60** (`dense_split.json` `next_tic_runs.unseen_ids`) | 60 | **51 (85%)**: ids 0-24 and 26-51; 18 / 16 / 17 on maps 6 / 7 / 8. Ids 52-59 are k = 1; id 25 has no weapon request and cannot be classified | **51**, with **3,704** executed switch rows |
  | unseen pool sample, ids 61:3000 step 61 | 49 | 0 | 0 |
  | **candidate replacement, ids 60:120** | 60 (20 per map) | **0**: 59 with k = 1 to 5, one unclassifiable | **0** |

  arenas_678 was started three times (`arenas_678/RECORDING_LOG.txt:1-3`: 16, 20, then 16 workers). Every restart gave every worker a fresh k = 0 episode, so k cannot be read off `worker_*.jsonl` line order for that segment. arenas has one start (`arenas/RECORDING_LOG.txt:1`), and k = id // 32 there, confirmed on all 8,000 log rows (Astra) and on raw widths of ids 33, 35, 1999, 6000, 6001, 7002 (k = 1, 1, 62, 187, 187, 218).
- **Why it matters.** The unseen row would measure maps 6 to 8 under a different control distribution (weapon selects that execute, weapon changes on request) than val and test, which never exercise those bits. In the control embedder (`backbones.py:153-181`, Linear, SiLU, Linear plus positions, zero weight decay) a first-layer column receives gradient only when its bit is 1, so the weapon-bit columns learn only from the histories of the 32 k = 0 training episodes. Map transfer and control-regime shift would be confounded.
- **What to do.** No dense unseen score exists yet, so declaring a replacement now is not outcome selection (Astra agrees). Declare before launch a primary unseen subset of verified k ≥ 1 episodes. Ids 60:120 qualify (20 per map, no executed switches); a fixed-seed map-stratified sample from the whole remaining pool is the stronger option. Keep 0:60 as a documented secondary set reported with its k strata. Add the new subset to `dense_split.json` under a new key rather than editing the frozen one.

### H2. The evaluation wrapper does not seal the test set and can report stale, mislabelled or incomplete numbers

- **Evidence (code).** `scripts/spiderman/after_nexttic.sh`:
  - `:43,162-191`: every corpus in `CORPORA` (default `val test arenas_678 seen unseen unseen2`) is scored for live, EMA and `best.pt` in one pass. No validation-only stage and no recorded selection precede test.
  - `:194-230`: test rollouts run whenever the test latent directory exists, independently of `CORPORA`, so `CORPORA=val` still rolls out and scores test. Rollouts and h4 use live weights only (`:185,199`). The wrapper has no validation rollout stage and no unseen rollouts.
  - `:174`: output directories are not keyed by checkpoint, decoder or sampler. `:53`: stages are skipped on file existence. `:216`: `prov` writes the current checkpoint into the provenance of a cached rollout. `:113`: the `_best` variant is stamped with `PICK`.
  - `:94-101`: tuned or stock decoder is chosen by which weight files exist.
  - Evaluation silently scores whichever requested episodes have a sidecar: `list_latent_episodes` drops latents without sidecars (`doom_data.py:196-207`) and `TicWindowDataset` intersects with the requested ids without asserting completeness (`:632`); `eval_tf.py:218` calls it directly. Training has a completeness guard (`train_wm.py:150-167`); evaluation does not, so the C4 and C16 rows could be scored on different episode sets without warning.
- **Confirmed by** reading the control flow; Astra confirmed independently and found the `CORPORA=val` test rollout.
- **What to do.** Split into a validation stage (val TF, val rollouts, sampler, decoder and live/EMA choice, written to a hashed selection file) and a final stage that refuses to start without that file and scores test and unseen once. Key every output by checkpoint hash, variant, decoder hash, sampler settings and window manifest. Assert the exact requested episode set in every evaluator. This can be built while training runs.

### H3. The launch gates do not verify the training corpus and do not pin what launches

- **Evidence (code).**
  - `scripts/cluster/gates.sh:73-84,137-143` audit sidecars against raw parquet for val only (both latent spaces). The 300-step smoke reads the training corpus but checks nothing about it.
  - Gate 2 (`:79-85,146-151`) reads sidecars only; gate 5 (`:212-223`) accepts any finite `psnr_raw`.
  - The encoder's decode check (`encode_parquet.py:174-190,697-702`) round-trips freshly encoded frames of the first episode; it never reads the stored latent array.
  - `RESEARCH_CONTEXT.md` 2026-09-22 21:30: train shard 0 was written by the old encoder with wide sidecars and normalised afterwards; shard 1 by the new encoder.
  - `scripts/spiderman/launch_nexttic.sh:157` runs `git pull -q` after the gates, and a failed pull does not stop the launch (`set -u` only, `:59`). `scripts/cluster/launch_runs.sh` requires no gate receipt.
- **What goes undetected.** A latent array shifted by a row against its sidecar; a shard encoded under a different contract; an orphan latent left by an interrupted write (`encode_parquet.py:202-203,254-261`); code that differs from the gated code.
- **What to do.** Section 7.1, items 1, 2 and 4.

### H4. Decoder provenance: documented decoder recipes include the unseen maps, and the planned dense decoder tune would train on val and test episodes

- **Evidence (code).** The historical tuned decoders were trained with `--in-dir $D/raw_arnold --split $D/split_arnold.json` (`scripts/spiderman/vae_gate.sh:32`), the 17-map corpus whose training maps include arenas 6, 7 and 8. The planned MSE-only tune streams from `raw_arnold_dense/arenas` (`scripts/spiderman/decoder_mse.sh:42`). `finetune_decoder.py:134-160` (`sample_row_groups`, called at `:296`) samples row groups from every file in that directory, including val 6000:7000 and test 7000:8000, while `:346` records `split_subset: "train"`. The installed decoder artifacts themselves were not inspected (server only).
- **What to do.** Before any dense decoder tune, restrict sampling to an explicit id list (train 0:2000) and record the selected episodes and row groups. Until a train-map-only decoder exists and its manifest is verified, every arenas_678 number is "unseen by the dynamics model", not "unseen by the system".

### M1. Few-step sampler numbers depend on an untuned timestep spacing

- **Evidence (arithmetic; Astra reproduced it exactly).** `diffusion_v.py:114` spaces DDIM steps uniformly in t over linear betas 1e-4..0.02. The 4-step times [999, 666, 333, 0] sit at SNR [4e-5, 0.011, 0.47, 9999]: two of the four network calls are at essentially pure noise, and the whole range from SNR 0.47 to clean is one jump. At 50 steps, 16 calls are below SNR 0.01, 26 below 0.1 and 13 above 1. SD's scaled-linear schedule would put the same four t at SNR [0.005, 0.117, 1.15, 1175].
- **Consequence.** The step-sweep numbers stay valid for the stated sampler. They do not show the best 4-step quality the model can reach, and the gap to GameNGen's 4-step behaviour may be partly a spacing effect. That link is a hypothesis: low-SNR calls can still set scene structure. Before any claim about few-step quality or evaluation cost, sweep the spacing on validation: uniform t against uniform log-SNR at 4, 8 and 16 steps, DDIM-50 anchor, paired windows and noise, teacher-forced and rollouts. Keep the trained betas and change only the chosen indices. Evaluation-only, no retraining.

### M2. Uncertainty is reported as if windows were independent; per-map output omits the raw metrics

- **Evidence.** `eval_tf.py:317` reports `sem = std / sqrt(n)` over windows; `:319-320` per-map output carries decoded PSNR and LPIPS only.
- **Exploratory estimate** (raw persistence only, 10 convenience-sampled arenas episodes, 150 windows each, gap 1): per-window SD 5.27 dB, SD of episode means 1.61 dB, intraclass correlation about 0.09 (not corrected for the sampling variance of the episode means). At 100 episodes and 2,048 windows that implies a clustered SE near 0.19 dB (design effect about 2.8) against an iid 0.12. At gap 4: ICC about 0.17, SE near 0.16. The unseen set has three maps, so any statement about transfer across maps rests on n = 3. The per-window distribution is heavy-tailed (near-static frames score above 35 dB).
- **What to do.** Report paired, episode-clustered bootstrap intervals (resample episodes within map, same windows for every model), computed on the actual model scores. Put raw metrics and raw persistence in the per-map block. Report PSNR of pooled MSE or a median beside the mean.

### M4. Rollout scoring selects surviving lives and carries no motion measurement

- **Evidence.** `rollout_eval.py:54` requires the seed and the whole horizon inside one life; on the 12 local episodes Astra measured 34% of L32/H256 candidate windows excluded against 3.7% at H1. Episodes are drawn uniformly and starts with replacement (`:64-68`). `persist_last_*` uses the real previous frame (`:359`), so it is a local-difficulty reference, not an open-loop competitor; copy-seed is the right floor, but a frozen model scores it. `motion_audit.py` (frame-difference and flow ratios) is not called by `after_nexttic.sh` and is written for the old C4, decoded, 64-step layout.
- **What to do.** Freeze one H256 manifest and reuse its prefixes for every horizon; report the excluded fraction per map; put prediction-to-real motion ratios beside every drift curve.

### M5. FVD and the IDM measure narrower things than their captions suggest

- FVD reads only the first 16 or 32 frames (`fvd.py:60`): 0.46 s and 0.91 s at tic spacing, 64 and 128 tics for the stride-4 clip. The I3D file comes from a mutable `main` URL (`:20`); score, frame count and clip count are saved but not the features or the weight identity (`:64`). At 256 clips the feature covariance is estimated from few samples relative to its dimension, so the estimate is biased; compare only at equal N and state it. Pin the I3D hash, save features, add pre-declared late windows.
- The IDM judges the 29 requested action ids, not the 19 executed bits (labels from `action`, `rollout_eval.py:133,484`), only on verified decision tics, and `judged()` keeps the longest run before checking that it joins the seed (`:429-467`, `max(runs)` at `:455`), so a rollout whose valid first run is shorter than a later run is skipped entirely (Astra reproduced it). Enumerate every eligible window instead, and report class-wise accuracy.

### M6. The equal-game-time comparison is a system comparison, not a spacing ablation

`eval_tf.py --horizon-tics 4` is indexed correctly (`:248-270,289,301`), but windows are drawn independently per dataset (`:226-227`) and keyed by dataset index (`:250`), so h1, h4 and the stride-4 rows are not paired. Context spans differ (0.91 s against 3.66 s), and the per-tic corpus keeps the override tics the stride-4 corpus dropped. Publish one manifest of `(episode, seed-end tic, target tic)` shared by all rows, and call the result "equal elapsed time", not a stride effect.

### L1. Dataset card and index errors

- `index_arenas.parquet` and `index_arenas_678.parquet` have `kills = deaths = -1` in all 11,000 rows (verified); the worker logs hold the real values (for example `arenas/worker_00.jsonl:1`: kills 16, deaths 4).
- The card says the parquet metadata carries "WAD, seeds, kills, deaths"; a default per-tic file carries only `seed_scheme, corpus_id, episode_id, map_id, seeds` (`record_arnold.py:193-204`, verified on 64 files).
- The card calls `tic` the "engine tic inside the episode". It is the recorder's counter (`record_arnold.py:237,274`): in all 12 local episodes it steps by exactly 1 across every respawn, and the roughly 39 respawn tics per death are never recorded (`release/DENSE_CORPUS.md:85-94`). Window validity is unaffected because the `deaths` rule cuts lives.
- The card lists unseen as all 3,000 episodes; `dense_split.json` `ranges.unseen` is 0:60.
- "Bit-for-bit reproducible" from corpus id and episode id (`DATASET_CARD.md:159-160`, `DENSE_CORPUS.md:40`) holds only given the recorder's start history: the same episode re-recorded as a process's first episode would execute weapon switches the corpus copy did not.

### L2. Provenance and robustness gaps

- The resume fingerprint hashes the header, both file sizes, three 64 KiB latent windows and the whole sidecar per episode (`train_wm.py:280-281,302-345`): sampled-content hashing, not exhaustive.
- A restarted encode shard rewrites `encode_meta_NN.json`, so the old encoder's record for shard 0's first episodes is lost unless it was copied. The metadata records a VAE id, not a resolved weight revision (`encode_parquet.py:614-633`).
- `eval_tf.py:328` reports `sampling_frames_per_s` as windows per second; at `--horizon-tics 4` the generated-frame rate is four times higher.
- The beta schedule is not stored in checkpoints (`diffusion_v.py:14`); a sampler sweep must record both the trained schedule and the inference index list.
- Snapshots are bf16 and recovery checkpoints fp32; `pick_checkpoint.py` prefers the recovery file at equal steps. Record which one each score came from.
- No final save on manual stop (`train_wm.py` loop ends only at `--steps`); stop at a completed checkpoint.

## 3. Suspicions (not confirmed)

1. **Train and eval latents may differ numerically.** bf16 encoding depends on batch shape (`encode_parquet.py:132-135`; the earlier measurement found 60% exact agreement between batch 64 and 16). Train shard 0 (old encoder), shard 1 (new encoder) and the eval corpora came from different processes and maybe cards; a move to rented H100s could mix hosts. Record host and settings and verify numerical equivalence before combining encodes.
2. **Library versions differ per backbone on Spiderman** (M3); the installed environments were not inspected.
3. **Noise augmentation may be easier to undo at tic spacing.** One level q is shared across the 32 context frames and the noise is i.i.d. per element (`diffusion_v.py:142-151`). Consecutive tics are nearly identical, so the network can average i.i.d. noise across frames, while real rollout error is correlated across frames. Magnitude and backbone dependence are unmeasured; watch rollout drift against copy-seed early (section 7.2).
4. **The U-Net's new class-embedding table** (`backbones.py:355-356`, default N(0,1) rows, norm about 36) perturbs the pretrained time embedding at step 0. The finished stride-4 U-Net recovered from the same construction; the cost in updates is unmeasured.
5. **Existing numbers on Spiderman** (`results_spiderman/**/metrics.json`, installed decoder `metrics.json`) were not readable from here; every statement about them rests on `RESEARCH_CONTEXT.md` and the dossier.

### Is the protocol frozen before launch?

Partly written, not enforced. ## 6. One real episode, end to end

Traced for training episode arenas `ep_01999` (map 5, k = 62) through the code, and against the raw file where local data allowed.

1. **Recording.** `record_arnold.py:237-274`: per tic, store the frame, tic, action, button string and game variables, then `make_action(buttons, 1)`; on death, break, respawn, reset the network; `deaths` rises by one on the first stored row of the new life. Raw file: 4,974 rows, tic 0 to 4973 in steps of 1, 7 deaths, raw button widths up to 636 (k = 62), 222 unexecuted switch rows, 0 executed.
2. **Encoding.** `encode_parquet.encode_episode` (`:193-271`): `--every-tic` keeps all rows (`:216`); frames decoded, scaled to [-1, 1], padded to 320×256, encoded (posterior mean, bf16 autocast), normalised `(z - shift) * scale`, saved fp16 `(T, C, 32, 40)`; the sidecar stores `buttons[:19]` padded, `buttons_raw_len`, `switch_requested_index`, the raw metadata and `is_decision`/`chain_id`. Not verifiable locally: the stored latents and sidecars themselves.
3. **Windows.** `TicWindowDataset` (`doom_data.py:618-701`) checks columns, lengths and control width and computes `tic_window_starts(meta, 32, 1)`; an item is context `lat[s:s+32]` reshaped to `(32·C, 32, 40)`, target `lat[s+32]`, controls `(32, 19)` from rows s to s+31.
4. **Loss.** `train_wm.py` loop: `noise_augment` (one q per sample, bucket) on the context; t uniform in 0 to 999; `VDiffusion.training_loss` v-MSE in fp32; backward; clip; spike check; AdamW step; EMA every 8.
5. **Checkpoint.** Recovery every 5k (fp32 model and EMA, optimizer, scheduler, episode pin, corpus fingerprint); bf16 snapshot every 10k; `best.pt` on noisy-context validation loss.
6. **Evaluation.** `pick_checkpoint.py` picks by stored step; `eval_tf.py` rebuilds the model from the checkpoint's recorded interface, draws windows, samples DDIM with keyed noise, decodes, reads the raw frame at the exact target tic (`RawFrames.get`, equality-checked) and computes PSNR, LPIPS, HUD PSNR, persistence and reconstruction. `rollout_eval.py` rolls 256 tics with controls shifted each step, scores against raw frames and writes clips; `fvd.py` scores the first 16 or 32 frames.
7. **Where the trace could not be followed:** the encoded sidecars and latents, the `encode_meta` records, installed decoder provenance, the IDM checkpoint's training data (`train_idm.py` was not read in full), and the two Python environments. All are on Spiderman.

## 7. What to measure

### 7.1 Before launch (conditions for GO)

1. **Training-corpus inventory and sidecar audit.** Exact id inventories and complete latent/sidecar pairs for train (2,000) and val (100) in both latent spaces; the sidecar-to-raw audit over all of them, zero mismatches.
2. **Stored-latent alignment.** Per shard, re-encode about 64 stored frames (including a tail batch) with the recorded settings and compare with the stored latents; decode both through one decoder; compute `vae_psnr` (`eval_tf.py:292`) on sampled training and val windows as an alert, with deliberately shifted ±1 and ±4 row negative controls; report per shard, not only pooled. Verify matching encoding contracts within each latent space.
3. **Smoke additions.** Emitted-window check on actual samples (newest control = row r-1; changing `buttons[r]` leaves the sample unchanged); finite nonzero gradients and parameter updates in the control MLP, positions, inflated context conv and SD 3.5 `pooled_control` by step 300; finite nonzero output sensitivity to the newest controls under fixed noise (directional correctness is assessed separately, in 7.2); readback of live and EMA at h1 and h4; a 10-update recovery resume; production then starts fresh from public weights.
4. **Pin what launches.** Remove the post-gate `git pull`; record the SHA, resolved commands, data identities and encoder revisions in the gate report and have the launcher refuse anything else. Confirm host-memory and disk headroom for a recovery save.
5. **Commit the revised unseen subset** (H1) before any score exists.

Required before comparative scoring, not before training: one pinned scoring environment for both rows; the split validation and sealed-test stages (H2).

### 7.2 First day and the first 20k updates

- Every validation (1k): loss overall and by t quartile against the audit's planning bands (U-Net about 0.30 / 0.24 / 0.225 / 0.21 at 1k / 5k / 10k / 20k; SD 3.5 about 0.19 / 0.14 / 0.128 / 0.118). These are forecasts, not thresholds.
- Continuously: pre-clip gradient norm and clip fraction, finite and non-finite skips separately, update ratios of the control MLP and positions (not in the built-in probe list, `train_wm.py:769`), updates/s, data-wait fraction, peak GPU and host memory, disk growth.
- At 10k and 20k (and 5k from the recovery checkpoint), live and EMA from the same saved file, stock decoder, on a fixed 512-window val manifest: raw PSNR and LPIPS against raw persistence and reconstruction on the same windows; the control-sensitivity probe; a directional check (swap TURN_LEFT and TURN_RIGHT on turning windows and measure whether the predicted frame shifts the opposite way); a 16-rollout × 256-tic val rollout with copy-seed and the motion ratio, to catch a model that learns persistence and ignores controls.
- At 10k: the paired 4/8/16/50-step sweep with both spacings (M1), to size the evaluation budget early.
- Stop rules as in the audit: restart only for a contract fault; hold and diagnose if the run is still at least 0.3 dB below persistence at 20k with under 0.1 dB improvement, with episode-bootstrap evidence and after evaluator and decoder checks. Stop at a completed checkpoint, since there is no final save on interruption.
