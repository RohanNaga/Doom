## Corrections and verified details

- PixArt-alpha is compatible with the SD1.x latent family (4 channels, scale 0.18215). The SD ft-EMA/ft-MSE model card states that only the decoder was fine-tuned. PixArt-Sigma 512 uses **SDXL VAE, scale 0.13025**, as explicitly specified by its official README and 512 training config. Equal channel count does not establish equal latent coordinates. Do not use Sigma with the fixed encoded corpus as if compatible.
- Official original DiT releases are XL/2 at 256 and 512, with the same depth, width and patch size. No verified larger drop-in original-DiT checkpoint found. **A larger diffusion transformer in SD1.x latent space does exist: UniDiffuser's released 1B U-ViT.** Its official README states the pretrained Stable Diffusion autoencoder; its released VAE config specifies four channels and scale 0.18215. It is a joint image/text diffusion model with auxiliary CLIP-image latents, not a scaled adaLN DiT; adaptation must handle those inputs and its joint-noise semantics. Hunyuan-DiT 1.5B and Lumina-Next 2B are real larger releases, but use SDXL VAEs. This is a checked candidate set, not an exhaustive catalog.
- 90k x 32 = 2.88M sampled training targets, not independent images. Original DiT XL/2's headline 256 model trained for 7M updates at batch 256 (1.792B exposures). This is scale context, not a required minimum for Doom.
- Current patch projection is trainable, shape (1152,132,2,2). Context is first 128 channels, target last four. Zero context initialization does not prevent gradients. Both backbones use it; no unfreezing needed. At L32 each patch has 132x4=528 scalar inputs projected to 1152, so there is no dimensional rank bottleneck at that projection. Spatial tokens stay 320 when L changes.
- Local meta-device inspection confirmed DiT parameter/state-key ordering and U-Net core ordering align for current EMA serialization. EMA math is fp32. best.pt has **no EMA**; eval loaders silently fall back to live if the key is absent. Use recovery checkpoints or compact snapshots with a non-null EMA and verify keys/shapes before interpreting --use-ema.
- EMA decay 0.9999 has about 6,931-update half-life and 10k-update mean age. It can lag improving live weights; evaluate generated quality as well as v-loss.
- Resume restores optimizer LR and scheduler base_lrs. A local AdamW/LambdaLR demonstration confirmed a new 1e-4 setting becomes saved 5e-5 after restoration. An LR branch requires an explicit, tested post-restore override; --resume plus --lr is not sufficient. No such override flag exists today.
- ImageNet is natural-image pretraining too. The relevant asymmetry is corpus breadth, resolution, conditioning and training history. Both original DiT and SD1.4 predict epsilon; both must adapt to velocity. SD1.4 did not learn action conditioning, temporal context or GameNGen history corruption during pretraining. Its model card describes multiple LAION subsets and stages; avoid asserting a single exact 400M-image training count.

## Ranking by evidence gained per remaining GPU-day

1. EMA/live paired diagnostics and fixed validation sampling: --use-ema on a verified EMA-bearing snapshot, 128 teacher-forced validation windows at DDIM50, plus fixed-corruption loss. Apply the same reporting policy to both backbones; no training day needed.
2. Compute accounting / modest compute-matched extension: benchmark both without checkpointing at their actual accumulation configuration, inspect log intervals across resumes and contention. Illustrative 1.6/1.4 updates/s gives 102,857 DiT updates versus 90k U-Net, or 90k DiT versus 78,750 U-Net. This ratio is not a measurement of the running histories. Original pair retains its 90k endpoints. Any extension is a separate branch, includes all prior compute, and stops at equal budget.
3. Full DiT seed 1, identical recipe: --seed 1 --lr 5e-5 --warmup 2000 --global-batch 32 --context-frames 32 --action-dropout 0 --steps 90000 --require-verified-transitions; preserve original warm start, split and noise recipe. First hour checks independent seed/provenance, valid updates and completion forecast, never early-loss selection.
4. PixArt-alpha 512 feasibility pilot: retain shared L32/v-loss/lr recipe, inflate input with context zeros, learn one action token in the caption input space and a separate bucket embedding in the timestep path; retain native position handling, slice epsilon output channels by patch layout, no T5 needed. Requires new wrapper/CLI support. Gate on exact latent contract, expected checkpoint-key loads, finite forward/backward (B,4,32,40), action/bucket dependence, throughput/memory and a tiny-batch learning check. One hour does not establish eventual quality. If admitted, give it a full prespecified budget regardless of early ranking and label as a third backbone package.
5. LR sensitivity: controlled forks from one recovery checkpoint at 2.5e-5, 5e-5, 1e-4; identical continuation batches and corruption, preserved optimizer moments, tested LR override. Roughly 500 updates each at shared rates fits a one-hour screen if setup is cheap. Continue at most one candidate only with consistent paired validation improvement (suggest practical threshold 0.002 over control, across two checks) and no stability regression. Threshold is a budget heuristic, not literature or statistical significance. More meaningful confirmation requires 2–5k updates. Keep original row and count tuning compute.
6. DiT-XL/2-512 warm start: existing --warm-start accepts that checkpoint; preserve current 320x256 data and position grid. First-hour load/head/shape check and matched 256/512 short starts, with no claim that early ordering predicts 90k. Same parameter count; does not address narrow ImageNet corpus. Do not treat it as a larger model.
7. L8: --context-frames 8 for a separate run. First hour ablate old 24 frames in the existing L32 model and benchmark L8. Compare evaluation on identical L32-eligible target windows; otherwise chain eligibility changes the data. L8 0.2532 vs L32 0.2535 at 5k is effectively tied, not evidence old context never matters. Attention tokens remain 320, so no 4x transformer saving. Full L8 run only if functional/throughput evidence is strong; paired L8 runs are needed to keep context identical between headline backbones.
8. Different context initialization / projection LR: first measure per-lag context gradient RMS, update RMS, projected activation magnitude, and validation loss with zeroed/shuffled recent versus old history. If useful history already affects predictions, leave zero initialization alone. A nonzero variant would be a new warm-start run (e.g. 0.1 times original target kernel on newest frame only), not surgery on a mature model. This coefficient has no established literature optimum. ControlNet supports zero-initialized added conditioning, not this specific coefficient.
9. Other schedule/optimizer/objective changes: keep batch32, wd0, clip1, uniform timesteps, velocity and current context-noise recipe. Uniform quartile gap does not single out a noise band; no excursions/clipping provide no reason to alter stability controls. Consider late decay only through the controlled LR branch. Learned variance, loss weighting, epsilon output wrapping or representation-alignment losses change the tested recipe; defer without an actual implementation failure.
10. More data: changes the question and requires both backbones to be rerun. One-hour train-versus-validation and coverage audit could motivate a later paired scaling experiment; no unilateral corpus expansion now.
11. Larger pretrained diffusion transformer: UniDiffuser 1B passes the SD latent-family gate; Hunyuan/Lumina do not. One-hour gate for UniDiffuser: audit the image, CLIP-image and text joint-denoising interface, marginalization/noise convention, rectangular position handling and estimate a full backward pass's memory/time. These require a new wrapper; no existing --backbone option supports it. Reject a day commitment unless those can be preserved and demonstrated without a new objective or data dependency. Prefer the simpler PixArt-alpha experiment even though it has fewer parameters.
12. Larger random-init DiT / parameter-matched scratch pair: no credible one-hour check can make a huge scratch model competitive at 2.88M exposures. Scratch pair is a legitimate separate low-data experiment but requires two models and gives up the useful warm starts. Current U-Net constructor always loads pretrained weights, so omitting --warm-start does not implement scratch U-Net. Defer.
