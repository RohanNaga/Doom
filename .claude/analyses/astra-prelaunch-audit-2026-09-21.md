### A1. Encoder, dtypes, normalization, padding and six-shard consistency

**Correct output contract.** `--every-tic` keeps every raw row, refuses a source declaring stored stride >1, and uses `--stride 4` only to derive verified decision flags/chains (`encode_parquet.py:130`). Episode filtering precedes sharding, but only in `select_paths`; each shard processes whole episodes and resets its batch boundaries at each episode (`encode_parquet.py:216`, `:166`). The sidecar copies the following columns if present; it does not force these dtypes itself. These are the dtypes of the actual Arnold recorder schema, so a source written with another schema must be checked (`encode_parquet.py:55`, `:155`; `record_arnold.py:291`):

### A2. Dataset, sampler, memory and file descriptors

**Correct indexing, verified locally.** For start `s`, L=32, target `r=s+32`, context is rows `s:r`, controls are rows `s:r`, target is row r; newest control is r-1 (`doom_data.py:635`, `:644`). Every one of the 32 adjacent edges across context and target must have tic delta 1, constant death count and constant map (`doom_data.py:456`). I compared the real `tic_window_starts` function with an independent brute-force implementation over **1,000 randomized** episodes/context/horizon/gap/death/map combinations: all matched. This confirms the implementation, not the server sidecars.

**Residual fail-open metadata defect, silent quality loss:** death and map checks are conditional on field presence (`doom_data.py:480`). A synthetic 70-row sidecar lacking deaths admits **38** L32 windows, including any unrecorded life boundary. The actual encoder normally writes deaths, so this is a corruption/import guard, not evidence that current recordings cross lives. **One-line fix:** require `tic`, `deaths`, `map_id`, `buttons`, `is_decision` and equal lengths explicitly for next-tic corpora; reject non-binary/width-mismatched controls.

**Uniformity.** Global dataset offsets count every valid start once. The training DataLoader shuffles all global indices without replacement and drops the final incomplete batch (`doom_data.py:603`; `train_wm.py:500`). Thus each valid window has the same inclusion probability, not each episode; longer continuous lives receive proportionally more windows. At most **31** valid windows are omitted per epoch, a fraction <3.2e-6 of ~10M. Episode map balance does not guarantee exact *window* map balance. An epoch boundary creates a fresh permutation and continues the same optimizer/EMA/LR/noise streams, with persistent workers retained (`train_wm.py:613`). Number of valid windows is **less than 10.07M** because context prefixes and death/gap exclusions are removed; use `dataset_summary.windows/32`, not exactly 314,687.5, as the true epoch length (`doom_data.py:607`).

**Seeding.** `accelerate.set_seed(0 + rank)` initializes the main streams. Worker seeds follow PyTorch DataLoader's base-seed-plus-worker-ID behavior; dataset lookup itself draws no random numbers. Diffusion timestep, target noise and context noise are drawn in the training process, not independently by workers (`train_wm.py:418`, `:619`; `diffusion_v.py:90`). Different worker settings/validation iterator creation can change later global RNG consumption and shuffle order; this is not duplicated worker corruption. The previous audit actually checked two epochs with 0/2/4 workers using **fork**, not the production 12-worker server process (`.claude/analyses/astra-nexttic-2026-09-20.md:492`).

**Memory accounting, using 10.07M tics as the supplied count.** Binary units below are GiB/MiB; decimal GB is explicit. Array sizes follow `doom_data.py:573`, `:586`, `:598`, `:648`; loader queue settings are `train_wm.py:499`, `:789`.

Metadata/window indexes are built **once in the parent**, before loader construction. Under Linux **fork**, workers inherit maps and metadata by copy-on-write; no per-worker index rebuild and no twelve independent 103/412-GB physical copies (`train_wm.py:492`, `:500`; `doom_data.py:551`). Arrays are read-only in the ordinary sample path. Some Python object/header pages become private. Under spawn/forkserver, NumPy memmap serialization can copy array contents rather than reopen files; the dataset has no custom worker reopening/state serialization. **Conditional catastrophic memory/I/O risk:** do not assume fork on every Python version. **One-line fix:** verify the server start method; provide per-worker lazy mmap reopening or explicitly choose a tested supported process context before using spawn/forkserver.

**FD count:** approximately **2,000 persistent latent mmap descriptors per dataset**; validation adds 100. Parent constructs both datasets before training workers start, so under fork each of 12 workers inherits approximately **2,100**, not 2,000+2,000 per worker per epoch. NPZ objects in this dataset are not retained in `self.episodes`; metadata arrays are materialized, so there is not another 2,000 permanently open sidecars (`doom_data.py:574`, `:598`). Main + 12 training + 2 transient validation workers imply about **31,500 descriptor-table entries per model**, plus pipes/logs/shared tensors; inherited entries can reference shared kernel open-file descriptions. **Crash risk:** a 1,024 soft FD limit fails during construction. Set soft limit **16,384** and verify <8,192 used per process; prefer lazy/LRU maps if tighter limits are unavoidable.

**RSS is not a fixed number derivable from these sources.** Worker baseline includes ~1.01 GiB shared metadata, touched model/parent pages inherited at fork, Python/torch libraries, and queued batches; each worker can also fault many GB of mapped file pages into its RSS. Those pages are physically shared page cache and must not be multiplied by 12 when estimating host use. Main holds fp32 model/EMA and later checkpoint copies too (`train_wm.py:463`, `:517`, `:683`). Budget metadata/queues at roughly **2–4 GiB per U-Net worker and 2–5 GiB per SD worker before file-backed RSS and inherited model pages**, as a provisioning estimate only; actual `/proc/<pid>/smaps_rollup` PSS/private/anonymous/file measurements are mandatory. Full train page cache across both latent spaces is **~480.18 GiB**, validation another ~24 GiB if fully resident. Random-window traversal eventually touches almost all train pages despite fewer than one target pass, because each target reads 32 preceding frames.

**Quality/cost verdict:** sampling is correct, but 12 workers is an unmeasured throughput choice, not a necessary correctness setting. Two jobs produce 24 persistent train workers plus four validation workers; queued payload alone approaches **4.84 GiB**, with pinned/shared copies and validation noise adding more. Prefer a measured **4/8/12 worker sweep with prefetch 2/4**; use the smallest setting within **5%** of maximum updates/s. FDs, PSS, available RAM and swap are gates. An RSS sum by itself is not evidence of a leak.

### A3. Trainer, optimizer, precision, validation, storage and recovery

Half-life **6,931 updates**; initial-weight mass is **36.79% at 10k**, **13.53% at 20k**, **0.0123% at 90k**. Early EMA may lag. ### A4. Diffusion and context corruption

**Correct implementation of the chosen objective:** 1,000 betas linearly spaced **1e-4…0.02**, cumulative alpha from float64, t drawn uniformly as an independent integer **0…999 per sample**, target `v = sqrt(abar)*eps - sqrt(1-abar)*x0`, plain elementwise MSE without SNR weighting or learned sigma (`diffusion_v.py:33`, `:58`, `:86`). Context corruption is separate from target diffusion. For q~U[0,0.7), one q per batch element broadcasts across **all 128 or 512 context channels and every spatial position**, while epsilon is independent per element. `c' = sqrt(1-q)c + sqrt(q)eps`; bucket=floor(q/0.7*10), so bucket 0 means **[0,0.07)**, not an exactly-clean training case (`diffusion_v.py:130`). No literal 4-channel assumption exists in the operations; the docstring's L*4 is stale. C=16 is handled correctly.

At q=0.7, signal amplitude is **0.5477**, noise amplitude **0.8367**, and unit-variance signal/noise power ratio is **0.4286**. Mean q is **0.35**; exactly clean context has zero probability in the intended continuous distribution (apart from vanishing finite-RNG endpoint probability). This is substantial corruption, not additive noise with standard deviation 0.7. Existing comments equating all public pretraining schedules with this schedule are too broad: SD 3.5 is native rectified flow, while the U-Net head is pretrained for epsilon; `backbones.py:714` explicitly retrains the former and `diffusion_v.py:9` should not be read as proving native-schedule parity.

**Quality verdict:** algorithmically correct, with a deliberate train/inference conditioning distribution mismatch and objective-transfer cost. The prior full noaug comparison is evidence of a tradeoff, not proof that q=0.7 is optimal for next-tic training. No rollout-robustness guarantee follows from Gaussian corruption. A mixture with per-frame independent levels, diffusion forcing, or self-forcing would be a different experiment; none is secretly implemented here (`diffusion_v.py:142`; historical results `RESEARCH_CONTEXT.md:171`).

### A5. Public pretrained backbones and step zero

**Input inflation is correctly zeroed.** U-Net has **128 context + 4 target = 132 channels**; SD 3.5 **512+16=528**. `inflate_input_conv` zeros the entire new convolution, copies the public pretrained kernel into its **last C** channels, and copies the bias. The forward concatenates `[context, noisy_target]` in that order (`backbones.py:236`, `:249`, `:357`, `:386`, `:746`, `:787`). Step-zero output is exactly independent of observation context in exact arithmetic, and the context-input weights get a nonzero first-step gradient from nonzero context. This is a sensible warm-start construction; it is not a randomly inflated 128/512-channel perturbation.

**What is not zero:** the retained backbone/output head; the new control MLP (ordinary Linear initialization); learned position table std **0.02**; U-Net's new noise-bucket class embedding initialized by the installed diffusers loader; SD's bucket token std **0.02**. U-Net's noise-bucket embedding has no explicit zero reset in our wrapper. SD's new pooled-control Linear **weight and bias are zero**, and `pooled_base` is zero, so pooled input is exactly zero at step 0 in history mode (`backbones.py:169`, `:355`, `:753`, `:758`, `:765`). Do not generalize the pooled zero claim to the old scalar-action path, whose pooled action embedding is random. At the first step the zero pooled projection blocks its upstream MLP gradient through that branch, but the joint-attention history branch still carries MLP/position gradients.

**Step-zero loss: a precise baseline is possible; a numeric real-model loss is not known.** Local NumPy integration of the exact beta schedule gives E[abar]=**0.2755132334**, E[1-abar]=**0.7244867666**. A zero-output model has expected per-element loss

`L_zero = 0.2755132334 + 0.7244867666 * mean(x0²)`.

For unit second-moment latents this is **1.0000**. An ideal epsilon predictor scored *without conversion* as v would have expected loss **0.4937023809 + 0.7244867666*mean(x0²)**, or **1.2181891475** at unit second moment. The actual public wrappers are neither zero-output nor ideal-epsilon predictors, and SD 3.5's head is native flow. Therefore **neither 0 loss nor 1 loss is a promised correct step-zero value** (`diffusion_v.py:58`, `:95`; `backbones.py:386`, `:714`). For real weights the exact expression is `E[pred²] + L_zero - 2 E[pred*v]`. Its empirical value and latent second moments must be recorded on the fixed smoke batch. A made-up “SD step-zero must equal X” would be a bad launch gate. Sane means finite outputs/gradients, exactly zero context dependence before updates, and falling fixed-batch loss after updates—not parity with CLIP-conditioned native inference.

**Text replacement is shape-valid, statistically different.** U-Net gets **[B,32,768]**, not the original 77-token CLIP sequence; bucket stays in class conditioning. SD 3.5 gets **[B,33,4096]** = 32 controls + one bucket token, through its context projection, with separate **[B,2048]** pooled conditioning from token **31 only**, plus base. No phase token is present. SD's 4096-wide stream replaces the native combined text-conditioning construction, not “32 CLIP tokens.” Learned positions encode chronology and prevent reducing history to an unordered multiset (`backbones.py:172`, `:199`, `:382`, `:770`). Attention supports variable token counts, so neither 32 vs 77 nor 33 vs the native text length is itself a crash.

**Norm scale:** no real token norms or native text embeddings were measured here. From Linear's default variance and position std 0.02, a Gaussian initialization approximation for k=0/3/10 pressed bits gives token RMS approximately **0.048/0.083/0.138** at width 768, and **0.044/0.081/0.136** at width 4096; L2 norms approximately **1.33/2.31/3.81** and **2.84/5.21/8.72**. These are Monte Carlo estimates of initialization statistics, not the seed-0 PyTorch tensors. SD bucket RMS is **0.02**, norm ~**1.28** (`backbones.py:174`, `:754`). This is much smaller than a hypothetical unit-RMS text stream, but CLIP/T5 learned feature scales are not safely inferred from a generic LayerNorm argument. The earlier reproduction itself initializes learned action tokens at 0.02, and the finished rows learned with small conditioning embeddings (`.claude/analyses/astra-nexttic-2026-09-20.md:229`).

**Keep the current token initialization for this launch.** Blindly forcing all controls to native text mean/RMS can amplify untrained K/V features and change pretrained attention behavior; padding to 77 tokens is not a principled fix. Log RMS of controls, positions, bucket, projected context, pooled input and their gradients at steps **0/1/100/300**. Require nonzero history/position gradients and measurable control sensitivity by 300; do not require a particular arbitrary norm. A normalization/learned-gain ablation is plausible but its gain is **unmeasured**, and “match pretrained embedding statistics” is not a known fix for these runs.

**Gradient checkpointing:** U-Net launch is off, SD on; the wrappers call diffusers' supported enable function (`launch_nexttic.sh:88`, `:120`; `backbones.py:376`, `:767`). This does not change the intended loss. Memory and recomputation overhead need real measurement with 32 history tokens; the old SD ~36.4-GB fit is a prior, not a new-history-mode guarantee (`launch_nexttic.sh:12`). Do not enable checkpointing on U-Net merely because it exists.

### B2. Mistakes that can waste the run or its evidential value

These are not owner taste choices:

1. **Starting before complete validated train/val pairs, or mixing VAE/revision/batch provenance.** The encoder's skip-on-latent and absence of corpus contract validation can conceal interrupted or mixed work; default trainer completeness protects missing pairs, not wrong contents (`encode_parquet.py:124`; `train_wm.py:155`). **Fix:** exact-ID/pair/content/contract audit first.
2. **Assuming the previous 36.4-GB fit or 12-worker default proves the new launch fits.** The new MLP/pooled/token pathways, queues and recovery save consume additional memory; six encoder table scans are substantial CPU work (`backbones.py:172`; `train_wm.py:366`; `encode_parquet.py:271`). **Fix:** test real batch32 including first Adam step, validation and recovery save under two-job host contention.
3. **Changing data or optimization semantics on resume because the current guard accepts it.** Verified remaining identity hole (`train_wm.py:171`, `:215`). **Fix:** immutable manifest/recipe verification.
4. **Using old multi-map decoders to label arenas6–8 “unseen by the system.”** Decoder provenance, not just the denoiser's initialization, defines that claim (`after_nexttic.sh:71`; `vae_gate.sh:32`). **Fix:** train-map-only decoder or qualify the claim as denoiser-only transfer.
5. **Calling decoded-ground-truth FVD a matched raw-video comparison, or comparing best-live against endpoint-EMA as an EMA ablation.** Both can silently pick a false winner (`rollout_eval.py:241`; `after_nexttic.sh:101`). **Fix:** raw targets and same-checkpoint paired variants.
6. **Training until the deadline and leaving no evaluation time.** The upper-bound400k launcher contains no freeze, final save or evaluation reservation (`launch_nexttic.sh:64`; `train_wm.py:702`). **Fix:** pre-budget inference calls and stop at a saved point that leaves the required scoring window.
7. **Treating point forecasts below as observed healthy thresholds.** The only available comparable learning curves are stride4 and different data/conditioning (`RESEARCH_CONTEXT.md:169`, `:181`). **Fix:** measure step0/300/1k baselines and use failure/trend/persistence criteria, not invented absolute loss certainty.

### B3. The ONE recipe change I would nominate before launch

**Give bucket0 an exactly-clean 10% training mass; keep the other90% variance-preserving q~U(0,0.7] in buckets1…9.** Keep executed actions, public start, architecture, batch, optimizer and the0.7 maximum unchanged. This is an explicit recipe proposal, not implemented in this audit. In code terms: draw a10% clean mask, leave those contexts bit-exact with bucket0, and map positive q to `1+floor(9*q/0.7)` clamped to9; save this policy in args/resume identity and expose it to validation and any inference-noise bucket mapping (`diffusion_v.py:130`; `train_wm.py:75`; `eval_tf.py:240`).

Reason: it repairs the **known** clean-context/bucket0 ambiguity while retaining90% robust-corruption training. It changes less than the old50/40/10 proposal, spends no extra GPU inference/training calls, and does not introduce an untrained CFG branch. The historical noaug TF gain and lack of benefit from adding inference noise motivate it, but do not prove it (`RESEARCH_CONTEXT.md:171`, `:172`). **Subjective expected effect: +0.05–0.15 dB TF, plausible range -0.1…+0.3 dB; FVD effect unknown.** I would not promise superiority to uniform0.7 from that evidence. If this small change cannot be implemented and tested symmetrically for both runs before launch, keep the decided recipe; do not delay useful training to pursue an unvalidated mixture. Operational/evaluation defects in B2 have priority over this optional improvement.

### B4. What must be fixed or decided before launch, versus what can wait

**Must freeze before the first production update to preserve a single-recipe claim:** tic spacing and row alignment; exact train/val source IDs and contents; VAE encoder/revision/scale/shift/padding/encode precision; public vs Doom start; context length and history/pooled/phase interface; v objective and schedule; context-noise/dropout/null policy (including whether future observation CFG is supported); global batch, optimizer/LR/warmup/WD/clip/EMA/spike-guard definitions. Decide corpus-completion/shard ownership and checkpoint/disk/host budgets before launch because operational failure can lose days.

**2. On the merits: near-zero terminal SNR plus v is a sound pairing, not proof of the best full schedule.** Write `x_t = a*x0 + s*eps`, `v = a*eps - s*x0`, where a²=abar and s²=1−abar (`diffusion_v.py:54`, `:58`). At a=0, **v=−x0 and the sampler's x0=−v remains finite** (`:62`); epsilon training instead has target eps=x_t at that endpoint and its usual x0 reconstruction divides by a (`:70`). This is the endpoint pathology addressed by [Lin et al., WACV2024](https://arxiv.org/abs/2305.08891), whose recommendations include zero-terminal-SNR rescaling, v-prediction and starting at the last timestep.

Our DDIM actually starts from pure Gaussian noise at **t=999** (`diffusion_v.py:108`, `:109`). Its training endpoint still contains **0.0063528*x0**, versus **0.0682649*x0** under native SD1.4 betas: **10.7456×** less signal amplitude. Noise coefficients are **0.9999798 versus0.9976672**. Thus our endpoint is closer to the inference prior, including conditional dependence on context. These coefficients are not a bound on perceptual error or high-dimensional distribution distance. Our SNR is **small, not exactly zero**, and the schedule is not explicitly zero-SNR-rescaled. Lin's argument favors retaining this endpoint over unmodified native betas; it does **not** prove DDPM-linear better than a zero-terminal-SNR-rescaled scaled-linear schedule. Do not silently apply endpoint rescaling at evaluation: that would use different coefficients from training.

**3. Mid-range differences matter beyond adaptation.** Uniform integer t induces a different distribution over SNR and therefore different training emphasis (`diffusion_v.py:91`, `:95`). Our **259/1,000 timesteps have SNR>1**, versus **354/1,000** natively; **74.1% versus64.6%** of draws are below1. For fixed x_t,t, v prediction error gives x0 error `−s*delta_v`, so v-MSE corresponds to x0-error weighting **1/(1−abar)**. Changing the schedule changes the mixture of those denoising tasks even after the time embedding adapts. DDIM also uses uniform spacing in t rather than SNR (`:109`), changing finite-step integration locations. The persistent differences in objective weighting and sampling discretization can help or hurt; they are separate from a stale pretrained time association and have no measured ranking here. The context corruption function uses its own variance fraction, independent of the target beta table (`diffusion_v.py:142`).
