# Astra round 9: methodology and one improvement

Independent proposal, 2026-09-16 brief; no run authorized or launched by this review.

1. Parameter count: the clean practical answer is PixArt 611.6M versus U-Net 860M: live seen 21.35/0.272 versus 21.36/0.270, about 29% fewer parameters; smaller PixArt also improves on DiT 675M seen LPIPS 0.311. These are descriptive means, not demonstrated equivalence. Capacity remains a confound for the original U-Net/DiT pair. Smallest next check: paired episode CI for the PixArt/U-Net LPIPS difference with an explicitly stated practical margin (e.g. 0.01), labeled exploratory, and replication before a general equivalence claim. No cheap extra row eliminates capacity causally; that needs a within-family size sweep with pretraining and conditioning controlled. Matching trainable counts by freezing or pruning does not match pretrained capacity. UniDiffuser's 952M and changed LR do not isolate size.

2. Framing: recommend "Practical choices for adapting pretrained diffusion models to Doom under a measured compute budget." Neither "best methodology" nor "initialization matters most" is identified by the present package comparison. The section-0 causal wording should be narrowed even though previously adopted. The source/unique-image/presentation axes must not be conflated. Existing 80k-target runs are sample-matched, not compute-matched by construction. Budget should name A6000 hardware and include adaptation, evaluation and tuning, while distinguishing inherited pretraining cost. A broader methodology would need a same-architecture checkpoint/initialization contrast, bounded LR robustness, one controlled rollout intervention, and replication of the proposed recipe. There is already a corrected-label 5k DiT context-length sweep (Sep 14 log), contrary to the brief's blanket no-context-ablation statement; it is not a final-budget cross-backbone ablation. Short LR forks only test local robustness, not full-run ranking robustness. SD v1-1 versus v1-4 is a potential same-architecture checkpoint contrast (backbone card), but changes multiple pretraining ingredients and does not isolate diversity.

3. Highest expected gain per extra card-day (judgment): EMA evaluation first (observed seen gain), inference context-noise tuning second (rollout hypothesis), DDIM step sweep third (efficiency hypothesis). EMA: DiT paper uses 0.9999; our U-Net seen LPIPS 0.270->0.250 and PixArt 0.272->0.255, with rollout benefit unestablished. Context noise: GameNGen motivates noisy-context training; Diffusion Forcing motivates selectable history noise; Oasis code supplies the inference precedent, not a published controlled Doom result. Do not transfer its 15/1000 index to our schedule. DDIM: GameNGen Table 3 has better teacher-forced metrics at a few steps than at 64; this motivates testing 4/10/20/50, not predicting a DoomDiT gain.

Thursday GPU3 proposal after video evaluation: U-Net live/EMA x training-scale context noise levels {0,0.035,0.105}, fixed DDIM50, same 64 development rollouts. Use training-matched corruption and bucket encoding; evaluator already exposes infer-noise. Separate context-noise and target-noise RNG streams: the current single-stream implementation does not preserve target noise across settings merely by reusing the seed. Select using validation rollout LPIPS over horizons 32/64 with motion/action guardrails; confirm selected versus clean baseline on full fixed reporting rollouts, seen/unseen TF, FVD16/32, motion and IDM. Keep original shared-recipe table distinct from tuned U-Net. Target one card-day, subject to measured rollout throughput; include zero as valid winner. No claimed gains until measured. A positive result motivates an inference-method lesson without retraining; a negative result removes an obvious alternative explanation of persistence.

4. Drop new architectures, automatic 180k continuation, REPA for this deadline, batch redesign and borrowed Matrix-Game history probabilities. REPA's card supports ImageNet/SiT convergence, not late-stage Doom U-Net rescue; Matrix-Game 1's history dropout belongs to a different training/CFG design. Preserve ongoing-row evaluations, release, and time for a second U-Net seed if resources remain. Correct first-open, causal architecture/pretraining language and equal-compute labels. Record the shared-recipe/model-package confounds and the curated campaign/arena split distinction.
